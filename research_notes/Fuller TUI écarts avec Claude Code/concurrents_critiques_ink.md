# Concurrents TUI, critiques de Claude Code et bonnes pratiques Ink (état 2025-2026)

Notes de recherche pour l'équipe « Fuller » (agent TUI open-source, Ink 5 + React 18 + TypeScript + Gemini API). Date des notes : 22 septembre 2026. Termes techniques laissés en anglais.

---

## Question 1 — Les concurrents (2025-2026) : frameworks TUI, features UX, raisons d'architecture

### Takeaway
Le marché s'est scindé en trois camps : (a) Ink/React (Claude Code — mais avec un renderer maison, Gemini CLI + ses forks Qwen Code, GitHub Copilot CLI, Amp en partie), (b) renderers natifs « cell-based » avec double buffer (Codex → Rust/ratatui, OpenCode → OpenTUI Zig+Solid, Crush → Bubble Tea v2/Ultraviolet, pi/Kimi Code → pi-tui), (c) Python (Aider prompt_toolkit+rich, Mistral Vibe Textual). Tous ceux qui ont quitté Ink ou Bubble Tea v1 invoquent la même cause : rendu « string-based » sans arbre de cellules ni diff cellule-par-cellule, donc flicker et coût CPU sous streaming de tokens.

#### Qwen Code (fork de Gemini CLI, Ink)
- L'issue #1778 « Ink Rendering And Flicker in Qwen Code: An Introduction » formalise le modèle : Ink écrit du texte par plusieurs writes par cycle (pas de « screens ») ; sortie **static** (`<Static>`, écrite une fois au-dessus et gardée comme historique) vs **dynamic** (tout le reste, redessiné à chaque update) ; **seuil critique : si hauteur dynamique ≥ lignes du terminal → chemin « clear-and-redraw » plein écran** (« the biggest flicker trigger »), très visible sous Windows/tmux/VM distantes/terminaux bas ; mode block-based (efface exactement la zone précédente) vs line-based/incremental ; Ink entoure ses updates de séquences synchronized output, ignorées par les terminaux non compatibles. Mitigations listées : garder la zone dynamique strictement sous la hauteur du terminal ; migrer le contenu append-only dans `<Static>` ; **découper le streaming par lignes : committer les lignes terminées dans `<Static>` et ne garder que la ligne en cours en dynamique** ; batcher les updates de streaming à 50–100 ms ; réduire les re-renders React ; évaluer `incrementalRendering` ; concevoir en supposant l'absence de synchronized output. — [Source](https://github.com/QwenLM/qwen-code/issues/1778)

#### OpenAI Codex CLI (TypeScript/Ink → Rust/ratatui, mai 2025)
- Annonce « Codex CLI is Going Native » (discussion #1174, 30 mai 2025). Quatre raisons officielles : (1) **zero-dependency install** (« currently Node v22+ is required, which is frustrating or a blocker for some users »), (2) **native security bindings** (sandbox Landlock/seccomp sur Linux, `sandbox-exec` sur macOS), (3) **optimized performance** (« no runtime garbage collection, resulting in lower memory consumption »), (4) **extensible protocol** (protocole filaire en JSON newline-delimited bidirectionnel défini dans `protocol.rs`, pour étendre l'agent en TS/Python). La discussion reconnaît que la TUI Ink était « easy to whip up and iterate » mais que le cœur est la boucle agentique. Réactions : « butter smooth », mais features manquantes au début (config, login). — [Source](https://github.com/openai/codex/discussions/1174) ; [InfoQ, juin 2025](https://www.infoq.com/news/2025/06/codex-cli-rust-native-rewrite/)
- La TUI Rust utilise ratatui (confirmé publiquement par l'équipe Ratatui / posts X). — [Source](https://x.com/AstraKernel/status/1920304287969689693)
- Architecture codex-rs (mars 2026) : workspace ≈70 crates ; `codex-tui` en **immediate-mode ratatui** (chaque frame redessine tous les widgets visibles dans des buffers intermédiaires, « sub-millisecond response times with no retained state to go stale ») ; snapshots `insta` obligatoires pour tout changement d'UI ; `codex-app-server` JSON-RPC 2.0 en modèle submit/event (`UserTurn`, `AgentMessageDelta`, `ExecCommandBegin/End`, `PatchApplied`, `TokensUsed`) qui découple les IDE du rendu ; gains revendiqués : plus de dépendance Node, plus de GC, démarrage en ms, fin de la croissance non bornée du heap en sessions longues. — [Source](https://codex.danielvaughan.com/2026/03/28/codex-rs-rust-rewrite-architecture/)
- Rendu : Codex entre par défaut en alternate screen (CSI 1049) ; PR #8555 (hjanuschka, mergée 9 janv. 2026) ajoute `[tui] alternate_screen = "auto" | "always" | "never"` et `--no-alt-screen` parce que Zellij suit strictement xterm (pas de scrollback en alt screen) ; en mode inline le transcript est écrit dans le scrollback à la sortie/suspension ; un pager de transcript existe via **Ctrl+T**. — [Source](https://github.com/openai/codex/pull/8555)
- Features TUI documentées : `/model`, `/approvals`, `/review`, `/diff`, `/status`, `/mcp`, `/resume`, `/compact`, `/undo`, `/init`, `/new`, `/mention`, `/personality`, `/experimental` ; `@` mentions ; images via `--image` ou collage dans le composer ; Ctrl+T transcript ; Esc-Esc pour éditer le message précédent ; souris/scroll ; thèmes ; `--no-alt-screen` ; notifications. — [Source](https://learn.chatgpt.com/docs/codex/cli)
- Problèmes connus côté ratatui inline : PR « Preserve inline TUI scrollback in Windows Terminal » (#39619, détection via `WT_SESSION`) ; demande `codex resume --history-lines` pour plafonner le replay de scrollback (#12945). — [Source](https://github.com/openai/codex/pull/39619) ; [Source](https://github.com/openai/codex/issues/12945)

### Inferences
- Le seul concurrent Ink « vanilla » à grande échelle est Gemini CLI, et même lui dépend d'un **fork** (`@jrichman/ink`) et de settings expérimentaux (`ui.terminalBuffer`, `ui.incrementalRendering`), signe qu'Ink upstream ne suffit pas à un agent de streaming sans travail supplémentaire.
- Le pattern gagnant chez les natifs (ratatui, Ultraviolet, OpenTUI, pi-tui, renderer Claude Code) est identique : buffer de cellules + double buffer + diff cellule + écriture atomique (DEC 2026). Pour Fuller, reproduire ce pattern *au-dessus* d'Ink (voir Q3) est le compromis réaliste ; le choix Bun-only d'OpenTUI le disqualifie pour un projet npm/Node.
- Le dilemme « alt screen (scroll applicatif, souris, mémoire constante) vs main screen (scrollback natif, Cmd+F, sélection native) » n'est résolu par personne : Gemini a activé puis désactivé l'alt buffer, Claude Code l'a rendu défaut pour les nouveaux utilisateurs seulement, Codex ajoute `--no-alt-screen`, pi-tui expose les deux renderers. Fuller devrait prévoir **les deux modes dès le départ** avec un toggle.
- Les features « table stakes » 2026 pour un agent TUI : @file avec fuzzy search, `!` shell mode, slash commands avec autocomplete, thèmes light/dark + ANSI + custom JSON, vim mode, transcript searchable, checkpoint/rewind, sessions resume, collage d'images (Ctrl+V + Alt+V fallback), statut/coût en footer ou sidebar, LSP/MCP status, ACP pour IDE.

## Question 2 — Critiques communautaires de la TUI Claude Code et réponses d'Anthropic

### Takeaway
Le flicker/scroll-jump a été « the single most reported issue in Claude Code's history » (plus de 1 000 upvotes cumulés) ; la cause structurelle est le choix de préserver le scrollback natif (donc redessiner tout à chaque changement) avec un Ink stock. #### L'explication d'Anthropic (Chris Lloyd, « I work on TUI rendering for Claude Code », HN ≈ janv. 2026)
- « we shipped our differential renderer to everyone today. We rewrote our rendering system from scratch and only ~1/3 of sessions see at least a flicker » (contre du flicker « in rapid succession » avant) ; patches upstream **DEC mode 2026 (synchronized output) acceptés dans le terminal de VS Code et dans tmux** ; recommandation : Ghostty (support 2026 natif, « zero flicker »).
- Cause racine : Claude Code utilise le **scrollback** (historique consultable) et non l'alternate screen comme Neovim ; en scrollback, tout changement au-dessus oblige à effacer et redessiner → flicker.
- Pipeline décrit comme « a small game engine » : React scene graph → layout → rasterisation en écran 2D → diff contre l'écran précédent → génération ANSI, dans un budget ≈16 ms dont ≈5 ms pour React→ANSI.
- Deux chantiers perf : (1) « Since we no longer have `<Static>` components the app re-renders much more frequently with larger component trees… Better memoization has largely solved that » ; (2) mémoire/GC : « The new renderer double buffers and blits similar cells between the front and back buffer… I ended up converting the screen buffer to packed TypedArrays ». — [Source](https://news.ycombinator.com/item?id=46701013)
- Stack déclarée (Pragmatic Engineer, Boris Cherny) : TypeScript, React + Ink, Yoga (layout), Bun (build) ; choix d'une stack « on distribution » pour que « Claude Code could build itself » (~90 % du code écrit par Claude). — [Source](https://newsletter.pragmaticengineer.com/p/how-claude-code-is-built)

#### Détails du renderer maison (analyse tierce du code source fuité, à prendre avec précaution)
- « Claude Code started with Ink, then forked it beyond recognition » : l'Ink stock « allocates one JavaScript object per cell per frame — on a 200x120 terminal, that is 24,000 objects created and garbage-collected every 16ms… diffs at the string level… no blit optimization, no double buffering, no cell-level dirty tracking ». Le renderer maison garde « React reconciler, Yoga layout, ANSI output » mais : **packed typed arrays** (2 × Int32 par cellule : `charId` | `styleId[31:17] | hyperlinkId[16:2] | width[1:0]`, width = Narrow/Wide/SpacerTail/SpacerHead), pools d'interning (`CharPool` ASCII fast path, `StylePool` avec transitions ANSI pré-sérialisées entre deux style IDs, `HyperlinkPool` OSC 8, reset toutes les 5 min), **double buffer front/back + diff cellule + damage rectangle**, optimiseur qui fusionne les écritures adjacentes et supprime les mouvements de curseur redondants, écriture entourée de **BSU/ESU `ESC[?2026h/l`**, métriques par phase (`FrameEvent`).
- Éléments DOM custom : `ink-root`, `ink-box`, `ink-text`, `ink-virtual-text`, `ink-link` (OSC 8), `ink-progress`, **`ink-raw-ansi`** (blocs pré-colorés injectés tels quels).
- `react-reconciler` en `ConcurrentRoot` ; throttle 16 ms (~60 fps) ; **le scroll contourne React** (timer 4 ms, mutation DOM directe + `markDirty()`) ; « blit » : les nœuds non modifiés et non déplacés copient leurs cellules de `prevScreen` (≈99 % des cellules en régime stationnaire), désactivé si overlay sélection/recherche, nœud absolu retiré ou layout décalé.
- Sélection (alt-screen uniquement) : mode souris SGR 1003, double/triple clic (timeout 500 ms, tolérance 1 cellule), récupération de « lost release » ; recherche : inverse + jaune + gras + souligné.
- Curseur déclaré via hook `useDeclaredCursor` pour l'IME (CJK) ; composant `AlternateScreen` qui émet `ENTER_ALT_SCREEN` dans un **`useInsertionEffect`** (avant le premier rendu, évite le flash) ; resize **synchrone** (non debounce) avec `ERASE_SCREEN` différé dans le bloc de paint atomique.
- Markdown streaming : LRU de 500 entrées sur `marked.lexer()` (survit au unmount), fast path `hasMarkdownSyntax()` (regex sur 500 premiers chars), **coloration syntaxique chargée en lazy via `Suspense`** (`cli-highlight`, 200–300 ms cachés), composant `StreamingMarkdown` tolérant aux fences non fermées puis bascule vers `Markdown` statique.
- Mémoïsation par **React Compiler** (slots par expression) sur un composant REPL de ~5 000 lignes ; **`OffscreenFreeze`** : cache les éléments React des messages hors écran pour que les timers (spinners) ne repeignent pas tout. — [Source](https://claude-code-from-source.com/ch13-terminal-ui/)

#### Le mode fullscreen (doc officielle « Fullscreen rendering », research preview)
- « draws the interface on the terminal's alternate screen buffer, like vim or htop, and **only renders messages that are currently visible** » ; « Only visible messages are kept in the render tree, so memory stays constant regardless of conversation length » ; input box fixe en bas ; le plus utile là où « rendering throughput is the bottleneck, such as the VS Code integrated terminal, tmux, and iTerm2 ».
- Défaut : fullscreen pour les utilisateurs ayant commencé **le 6 mai 2026 ou après** (ou première install ≥ v2.1.239 sans feature flags) ; classique si `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`, `tmux -CC`, SSH vers Windows, ou après échec de démarrage (fallback automatique, ≥ v2.1.236 : « started successfully once it has drawn its first frame and then either stayed up for 10 seconds… ») ; dialogue de proposition au plus 3 lancements.
- Souris : clic dans le prompt, clic sur suggestion `/` ou `@`, clic dans les menus (≥ 2.1.187), multi-select (≥ 2.1.208), `/config` cliquable + molette (≥ 2.1.271), clic pour déplier un tool result, Cmd/Ctrl+clic sur URL/chemin (UNC paths jamais liés pour ne pas fuiter les credentials Windows), drag-select avec copie auto au relâchement (Copy on select désactivable), double-clic = mot (frontières iTerm2), triple = ligne, Shift+flèches pour étendre, `Ctrl+Shift+c` / `Cmd+c` (kitty protocol) pour copier.
- Scroll : PgUp/PgDn (demi-écran), Ctrl+Home/End, molette ; auto-follow suspendu quand on remonte + bouton « Jump to bottom (3 new messages) » ; en-tête dim avec le dernier prompt hors écran (cliquable) ; `CLAUDE_CODE_SCROLL_SPEED` (0.25–20, défaut 1, 3 = vim) et `/scroll-speed` interactif ; accélération désactivable (`wheelScrollAccelerationEnabled`, ≥ 2.1.174) ; JetBrains : gestion spécifique (événements très fréquents, bugs 2025.2 détectés à l'exécution).
- Transcript : **Ctrl+O** bascule prompt ↔ transcript ; navigation style `less` (`/` recherche, `n`/`N`, `j`/`k`, `g`/`G`, `{`/`}` prompt précédent/suivant, Ctrl+u/d, Ctrl+b/f, `q`) ; **`[` réécrit toute la conversation dans le scrollback natif** (pour Cmd+F/tmux copy mode), **`v` ouvre dans $EDITOR** ; `/focus` = vue épurée (dernier prompt, résumé des outils avec diffstats, réponse finale).
- Presse-papiers : `pbcopy` (macOS), `wl-copy` / `xclip` / `xsel` (Linux, écrit aussi PRIMARY), PowerShell `Set-Clipboard` (Windows/WSL), tmux paste buffer, **OSC 52 en fallback SSH** (iTerm2 le bloque par défaut ; `/terminal-setup` l'active) ; toast indiquant le chemin utilisé.
- Opt-outs : `CLAUDE_CODE_DISABLE_MOUSE=1` (sélection native, garde flicker-free + mémoire plate), `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1` (≥ 2.1.195, molette seulement), touche de sélection native : Fn (Terminal.app), Option (iTerm2), Shift (VS Code/Cursor, autres).
- Dépannage : « Fullscreen rendering sends only the cells that changed between frames. Some terminals, most commonly Windows Terminal and other ConPTY-backed hosts, coalesce these positioned writes incorrectly » → `CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1` (auto sur Windows pour background sessions) ; Ctrl+L redessine ; tmux ≤ 3.6 sans synchronized output → plus de flicker ; `tmux -CC` incompatible ; `/diff` devient un panneau latéral en fullscreen. — [Source](https://code.claude.com/docs/en/fullscreen)

#### Configuration terminal (doc « Configure your terminal »)
- Shift+Enter : natif dans Ghostty, Kitty, iTerm2, WezTerm, Warp, Apple Terminal, Windows Terminal ; « Other terminals that support the kitty keyboard protocol, such as foot and Alacritty 0.16 or later — Requires Claude Code v2.1.269 or later » ; VS Code/Cursor/Zed/Alacritty < 0.16 : `/terminal-setup` écrit un keybinding (et sur VS Code met `terminal.integrated.gpuAcceleration` à `"off"` « to prevent garbled text » et règle `mouseWheelScrollSensitivity`) ; gnome-terminal et JetBrains : impossible → Ctrl+J ou `\`+Enter ; tmux : `set -g allow-passthrough on`, `set -s extended-keys on`, `set -as terminal-features 'xterm*:extkeys'`.
- Flicker sans changer de renderer : `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1` si le terminal supporte DEC 2026 mais n'est pas auto-détecté (ex. Emacs `eat`).
- **`[Pasted text #N +120 lines]`** : collage > 800 caractères ou > 3 lignes replié en placeholder, contenu conservé dans `~/.claude/paste-cache/` (rappel via l'historique), suppression atomique du placeholder par Ctrl+W/Ctrl+K, contenu marqué au modèle comme « pasted » (instructions internes non suivies sauf demande) ; caractères Unicode invisibles retirés à l'Enter avec notification ; le terminal VS Code peut perdre des caractères sur de très gros collages.
- Thèmes : `/theme` ou `/config`, option auto (détecte fond clair/sombre, suit l'OS) ; presets `dark`, `light`, `dark-daltonized`, `light-daltonized`, `dark-ansi`, `light-ansi` ; thèmes custom = JSON dans `~/.claude/themes/<slug>.json` (`name`, `base`, `overrides`), valeurs `#rrggbb`, `#rgb`, `rgb()`, `ansi256(n)`, `ansi:<name>` ; tokens : `claude`, `text`, `inverseText`, `inactive`, `subtle`, `suggestion`, `permission`, `remember`, `success`/`error`/`warning`/`merged`, `promptBorder`, `planMode`, `autoAccept`, `bashBorder`, `ide`, `fastMode`, `diffAdded`/`diffRemoved`/`…Dimmed`/`…Word`, `userMessageBackground`, `userMessageBackgroundHover`, `bashMessageBackgroundColor`, `memoryBackgroundColor`, `selectionBg`, `rate_limit_fill/empty`, `briefLabelYou/Claude`, variantes `*Shimmer` pour le dégradé animé du spinner, `<color>_FOR_SUBAGENTS_ONLY` (8 couleurs), `rainbow_<color>` ; hot-reload du dossier de thèmes.
- Vim mode : `/config` → Editor mode ou `editorMode: "vim"` ; NORMAL/VISUAL partiels (hjkl, v/V, d/c/y + text objects), `vimInsertModeRemaps` (ex. `jj` → Esc) ; Enter soumet même en INSERT.
- Windows : `^H` lu comme Ctrl+Backspace sauf mintty/cygwin → `CLAUDE_CODE_BS_AS_CTRL_BACKSPACE=0`. — [Source](https://code.claude.com/docs/en/terminal-config)

### Inferences
- La leçon centrale d'Anthropic : **un Ink stock + scrollback natif ne passe pas à l'échelle d'un agent streaming** ; ils ont dû (1) remplacer le pipeline de sortie (cellules, double buffer, DEC 2026), (2) abandonner `<Static>` au profit d'une mémoïsation agressive, (3) finir par offrir l'alt-screen. Fuller devrait prévoir dès le départ un « rendering backend » découplé des composants pour pouvoir suivre ce chemin.
- Les bugs récurrents « secondaires » à budgéter : fuites mémoire de caches (markdown/highlight, message list, memoCache), boucles de re-render idle causées par spinners/timers, réponses de capability queries qui polluent l'input (ordre de lecture stdin au démarrage), CRLF et `os.EOL` sous Windows, RTL/Indic/CJK width, palettes 16 couleurs sous SSH, thèmes clairs (ne jamais utiliser bright-black/color7 pour du texte « dim » sans tester en light).
- Le seuil « `[Pasted text]` > 3 lignes ou > 800 chars » et le cache de collage sont des choix produit copiables tels quels ; idem pour `[`/`v` en transcript (pont vers Cmd+F et $EDITOR) qui désamorce la principale objection à l'alt-screen.

## Question 3 — Bonnes pratiques et état de l'art Ink (v5 → v7, 2025-2026) pour une TUI sans flicker

### Takeaway
Ink a beaucoup bougé en 18 mois : `incrementalRendering` (6.5.0, nov. 2025), synchronized output DEC 2026 + kitty keyboard + `concurrent` + API curseur IME (6.7.0, févr. 2026), puis Ink 7 (avr. 2026 : `usePaste`, `useWindowSize`, `useBoxMetrics`, `useAnimation`, `alternateScreen`, `wrap="hard"`, `suspendTerminal`). Mais la règle structurelle demeure : Ink efface et réécrit la zone dynamique, et bascule en clear-screen complet dès que cette zone atteint la hauteur du terminal ; la discipline « zone dynamique courte + historique figé + batching + mémoïsation » reste obligatoire, et les projets sérieux finissent par patcher/forker Ink ou ajouter une couche de rendu par cellules.

#### Options `render()` et hooks (README Ink 7)
- `render(tree, { stdout, stdin, stderr, exitOnCtrlC (true), patchConsole (true — Ink intercepte console.*, efface la sortie, écrit, puis re-rend), onRender({renderTime}), isScreenReaderEnabled, debug, maxFps (30), incrementalRendering (false — « only updates changed lines instead of redrawing the entire output »), concurrent (false — Suspense/useTransition/useDeferredValue), interactive (auto : CI ou !isTTY → écrit seulement la frame finale, pas d'ANSI erase, pas de synchronized output, pas de resize, pas de détection kitty), alternateScreen (false — « scrollback buffer is not available… teardown output is disposable »), kittyKeyboard: { mode: 'auto'|'enabled'|'disabled', flags: ['disambiguateEscapeCodes','reportEventTypes','reportAlternateKeys','reportAllKeysAsEscapeCodes','reportAssociatedText'] } })`. En mode `auto`, Ink interroge le TTY (`CSI ? u`) et active le protocole si réponse sous 200 ms ; avec le protocole, `Ctrl+I` ≠ `Tab`, **`Shift+Enter` ≠ `Enter`**, `Escape` ≠ `Ctrl+[`, `key.eventType` press/repeat/release ; « Reusing the same stdout across multiple `render()` calls without unmounting is unsupported ». — [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)
- `<Static items>` : « permanently renders its output above everything else », pensé pour les logs/tâches terminées ; **« only renders new items in the items prop and ignores items that were previously rendered »** (modifier un ancien item ne re-rend pas). — [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)
- `useInput(handler, {isActive})` : appelé par caractère, mais un collage multi-caractères arrive en **un seul appel** ; `isActive` pour éviter les doubles traitements quand plusieurs hooks coexistent. `useStdin().setRawMode`/`isRawModeSupported`. `usePaste` active `\x1b[?2004h`. `useCursor().setCursorPosition({x,y})` (« essential for IME support ») avec `string-width` pour calculer x. `useAnimation({interval})` : « All animations share a single timer internally, so multiple animated components consolidate into one render cycle ». `suspendTerminal()` : Ink « stops writing output, stops consuming input, and restores the terminal modes the child expects (raw mode off, cursor visible, bracketed paste off, alternate screen exited, kitty keyboard protocol off) » puis repeint. — [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)
- `measureElement(ref)` → `{x, y, width, height, clientWidth, clientHeight}` ; **renvoie des zéros pendant le render** (appeler depuis `useEffect`/`useLayoutEffect`/handlers) ; pour un scroll view : mesurer le wrapper de contenu séparément, `flexShrink={0}` sur le wrapper (sinon Yoga l'écrase à la hauteur du viewport), clamp de l'offset à `content.height - viewport.clientHeight`, props `contentOffsetX/contentOffsetY` ; `useBoxMetrics(ref)` fait la même chose en hook (`hasMeasured`). `useWindowSize()` → `{columns, rows}` mis à jour au resize. — [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)
- Écosystème listé par le README : `ink-text-input`, `ink-spinner`, `ink-select-input`, `ink-link`, `ink-gradient`, `ink-big-text`, `ink-picture` (images), `ink-tab`, `ink-multi-select`, `ink-divider`, `ink-progress-bar`, `ink-table`, **`ink-markdown`** (Markdown coloré), `ink-syntax-highlight`, `ink-form`, `ink-task-list`, `ink-titled-box`, **`ink-scroll-view`, `ink-scroll-list`, `ink-virtual-list`** (« renders only visible items for performance »), `ink-use-stdout-dimensions`. — [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)
- `@inkjs/ui` : `TextInput` (autocomplete), `EmailInput`, `PasswordInput`, `ConfirmInput`, `Select`, `MultiSelect`, `Spinner`, `ProgressBar`, `Badge` (green/red/yellow/blue), `StatusMessage` (success/error/warning/info), `Alert`, `UnorderedList`, `OrderedList` ; theming via `ThemeProvider`, `extendTheme`, `defaultTheme`, `useComponentTheme` ; MIT ; version et limitations non documentées dans le README. — [Source](https://github.com/vadimdemedes/ink-ui)

#### Mécanique du flicker et de l'incremental rendering
- PR #781 (wu-json, mergée 12 nov. 2025 ; précédents abandonnés #751, #413, #708) : diff **ligne par ligne** entre frames, réécriture des seules lignes changées avec `cursorUp`/`eraseLines` ; limites : un changement de couleur/style dans une colonne marque toute la ligne ; sensibilité à la hauteur du terminal (rendu coupé sur petits terminaux) ; fonctionne bien quand la structure reste stable. — [Source](https://github.com/vadimdemedes/ink/pull/781)
- Issue #1023 (20 sept. 2026, master) : avec `incrementalRendering: true`, si la hauteur du terminal rétrécit de sorte que la frame remplit exactement le viewport, Ink n'émet que des déplacements de curseur (`\u001b[6A\u001b[E…`) sans réécrire le contenu → affichage décalé d'une ligne ; cause : la condition `outputHeight >= rows` supprime la newline finale et le diff ne voit aucune ligne changée ; PR #1025 ; contournement : désactiver `incrementalRendering`. — [Source](https://github.com/vadimdemedes/ink/issues/1023)
- Issue #450 : flicker quand un élément a une hauteur exactement égale à `process.stdout.rows` ; discussion #621 demande une option pour ne pas effacer le terminal quand la sortie dépasse l'écran. — [Source](https://github.com/vadimdemedes/ink/issues/450) ; [Source](https://github.com/vadimdemedes/ink/discussions/621)
- Modèle « fullscreen path » : « Ink takes its fullscreen path whenever the rendered output height is >= terminal rows, making every frame a clearTerminal + fullStaticOutput + output operation » ; garder la hauteur dynamique sous la hauteur du terminal et déplacer les historiques dans `<Static>`. — [Source](https://github.com/atxtechbro/test-ink-flickering/blob/main/INK-ANALYSIS.md) ; corroboré par [Qwen Code #1778](https://github.com/QwenLM/qwen-code/issues/1778)
- Ink a déjà eu ce bug côté « fullscreen » : v6.0.0 corrige « stale output when outputHeight changes from above stdout.rows to below stdout.rows ». — [Source](https://github.com/vadimdemedes/ink/releases/tag/v6.0.0)
- Comparaison OpenReplay : Ink « composes frames in JavaScript, diffs as strings, and writes to stdout » avec throttle 30 fps ; son plafond apparaît « under continuous output streams — model tokens, busy log viewers, or live dashboards ». — [Source](https://blog.openreplay.com/opentui-alternative-ink/)
- Retours de terrain Gemini CLI (voir Q1) : contention spinner/input dans le reconciler (#29295), artefacts du renderer incrémental au resize (#22615), CPU élevé au resume de longues sessions avec renderBuffer (revert du PR #23843), `<Static>` qui efface le scrollback (#28967). — [Source](https://github.com/google-gemini/gemini-cli/issues/29295) ; [Source](https://github.com/google-gemini/gemini-cli/pull/23843)

#### Clavier : Shift+Enter, kitty protocol, bracketed paste
- Sans protocole étendu, Enter et Shift+Enter envoient les mêmes octets ; encodages : **kitty** `CSI 13;2u`, **xterm modifyOtherKeys** `ESC [ 27 ; 2 ; 13 ~`, CSI-u (fixterms) `ESC [ 13 ; 2 u` ; kitty et Ghostty émettent CSI u nativement ; un renderer Ink modifié « pushes the kitty keyboard protocol's disambiguate flag when it starts and pops it when it stops » pour obtenir Shift+Enter dans iTerm2. — [Source](https://blog.fsck.com/agent-blog/2026/02/26/terminal-keyboard-protocol/) ; [Source](https://dev.to/richardbray/why-shiftenter-doesnt-work-in-claude-code-and-how-to-fix-it-10f7) ; [Source](https://github.com/autohandai/code-cli/pull/578)
- tmux : `extended-keys on` + `terminal-features 'xterm*:extkeys'` ; pièges connus : Windows aplatit Shift+Enter en CR avec modifyOtherKeys alors que le chemin kitty marche ; Alt+Enter confondu avec Shift+Enter ; à la sortie, **toujours désactiver le protocole** (Claude Code 2.1.85 : « terminal left in enhanced keyboard mode after exit… Ctrl+C and Ctrl+D now work correctly after quitting ») et ne jamais afficher « Shift+Enter » comme conseil si le terminal ne peut pas l'envoyer. — [Source](https://code.claude.com/docs/en/terminal-config) ; [Source](https://github.com/herdrdev/herdr/issues/3269) ; [Source](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Bracketed paste : `\x1b[?2004h` ; les collages peuvent contenir des séquences kitty (Claude Code 2.1.119 « multi-line paste losing newlines in terminals using kitty keyboard protocol sequences inside bracketed paste ») et des CRLF (2.1.119) ; pi-tui insère des marqueurs pour les collages > 10 lignes. — [Source](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) ; [Source](https://github.com/badlogic/pi-mono/tree/main/packages/tui)
- Réponses du terminal aux requêtes de capacités (`^[[?1;2c`, `22c`, couleur de fond, version) arrivent sur stdin et peuvent être tapées dans le prompt sur liaisons lentes (SSH, terminaux web) — corrigé en Claude Code 2.1.269 ; Gemini CLI interroge la couleur de fond toutes les 60 s (`ui.terminalBackgroundPollingInterval`) pour le thème auto. — [Source](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) ; [Source](https://geminicli.com/docs/reference/configuration/)

#### Images depuis le presse-papiers
- Approche OS : macOS via `osascript` (`the clipboard as «class PNGf»`), Linux X11 via `xclip` (lire `TARGETS` puis `image/png`), Windows via PowerShell ; **Ctrl+V sur macOS/Linux, Alt+V sur Windows** (Ctrl+V est intercepté par les terminaux Windows) ; drag & drop / chemin de fichier fonctionnent partout ; sous sandbox macOS, l'accès au presse-papiers peut être bloqué (`hiservices-xpcservice`). — [Source](https://www.jdhodges.com/blog/ctrlv-not-working-in-claude-code-heres-the-simple-fix-solved/) ; [Source](https://blog.shukebeta.com/2025/07/11/quick-fix-claude-code-image-paste-in-linux-terminal/) ; [Source](https://github.com/anthropics/claude-code/issues/17042)
- Gemini CLI : image sauvée dans `.gemini-clipboard/` puis référencée comme `@fichier` (PNG/JPG/GIF/BMP/WebP/TIFF, purge 1 h), raccourcis Ctrl+V / Shift+Insert / Alt+V (Cmd+V Mac). — [Source](https://github.com/google-gemini/gemini-cli/pull/13645) ; [Source](https://github.com/google-gemini/gemini-cli/pull/13997)
- Affichage inline d'images : pi-tui rend via protocoles graphiques Kitty / iTerm2 ; Ink dispose d'`ink-picture`. — [Source](https://github.com/badlogic/pi-mono/tree/main/packages/tui) ; [Source](https://github.com/vadimdemedes/ink/blob/master/readme.md)

#### Techniques de rendu confirmées par les acteurs (synthèse citée)
- **Synchronized output (DEC 2026, `ESC[?2026h` … `ESC[?2026l`)** : utilisé par Ink ≥ 6.7, pi-tui, le renderer Claude Code ; élimine le flicker sur Ghostty/kitty/iTerm2/WezTerm/VS Code (patché) mais pas sur tmux ≤ 3.6 ni Terminal.app (Claude Code 2.1.110 a dû corriger un rendu de démarrage « garbled » sur Terminal.app). — [Source](https://news.ycombinator.com/item?id=46701013) ; [Source](https://code.claude.com/docs/en/fullscreen) ; [Source](https://github.com/vadimdemedes/ink/releases/tag/v6.7.0)
- **Double buffer + diff par cellule + damage rectangle + TypedArrays** (Claude Code) ; **cell buffers + diffing renderer** (Ultraviolet/Crush) ; **tree de nœuds + rendu natif** (OpenTUI) ; **diff par lignes en CSI 2026** (pi-tui) ; **immediate mode** (ratatui). — Sources citées ci-dessus.
- **Mémoïsation** : Anthropic est passé à React Compiler et a dû corriger des fuites de `memoCache` ; réduction de 74 % des re-renders de l'input pendant un tour ; isolation du timer de spinner (50 ms) hors du shell parent ; caches de rendu markdown/highlight à borner. — [Source](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- **Scroll hors React** : Claude Code traite le scroll via un timer de 4 ms et une mutation directe du DOM interne (pas de setState) ; pi-tui et Gemini CLI implémentent un scrolling applicatif en alt-screen. — [Source](https://claude-code-from-source.com/ch13-terminal-ui/) ; [Source](https://github.com/google-gemini/gemini-cli/issues/10677)
- **Entrer en alt-screen avant la première frame** (`useInsertionEffect` chez Claude Code) et restituer l'historique dans le buffer principal à la sortie (Gemini CLI, pi-tui `TuiAltScreen`, Codex transcript-on-exit, Claude Code `[`). — [Source](https://claude-code-from-source.com/ch13-terminal-ui/) ; [Source](https://developers.googleblog.com/making-the-terminal-beautiful-one-pixel-at-a-time/) ; [Source](https://github.com/badlogic/pi-mono/tree/main/packages/tui)

### Inferences
- Pour Fuller sur Ink 5 + React 18, le plan le plus sûr est : (1) architecture « historique figé + zone vive minimale » : chaque message terminé est commit dans `<Static>` (ou, mieux, écrit directement dans le scrollback par un writer maison) et la zone dynamique = message en streaming + input + footer, **toujours < rows − marge** (tronquer le message en streaming à N lignes visibles et pousser les lignes terminées dans le statique, comme le recommande Qwen #1778) ; (2) batcher les chunks de streaming à 50–100 ms et n'exposer qu'un state « texte cumulé » mémoïsé (`React.memo` sur chaque message, clés stables) ; (3) `maxFps` bas (15–30) et un seul timer partagé pour spinners ; (4) émettre soi-même `ESC[?2026h/l` autour de chaque write d'Ink 5 (wrapper de `stdout.write`) puisque Ink 5 ne le fait pas ; (5) prévoir une migration Ink 7 / React 19 (ou un fork) pour `incrementalRendering`, kitty protocol, `usePaste`, `useCursor` (IME) et `alternateScreen` — ces quatre points ne sont pas reproductibles proprement sur Ink 5 sans patch.
- Le mode alt-screen impose d'implémenter soi-même : scroll virtualisé (ne rendre que les messages visibles, comme Claude Code fullscreen et `ink-virtual-list`), souris SGR 1003/1006, sélection + copie multi-chemins (pbcopy/wl-copy/xclip/Set-Clipboard/OSC 52), recherche style `less`, et une commande « dump to scrollback » pour rendre Cmd+F/tmux utilisables. Sans ces pièces, les utilisateurs rejettent le mode (Gemini 0.17.1).
- Les tests de rendu doivent couvrir : terminal < 24 lignes, resize (grandir/rétrécir d'exactement la hauteur de la frame), tmux, VS Code (GPU acceleration on/off), Windows Terminal/ConPTY, SSH lent (réponses de capability queries), thèmes clairs, CJK/emoji/Indic/RTL, collages CRLF et > 800 chars.

### Gaps
- Aucun benchmark public comparant Ink 5 vs Ink 7 (`incrementalRendering` + synchronized output) sur une charge de streaming LLM ; les gains sont décrits qualitativement (screencasts dans la PR #781, « fixes flickering in many modern terminals »).
- La feature `renderBuffer` mentionnée par Gemini CLI (PR #23843) et le setting `ui.terminalBuffer` ne correspondent à aucune option documentée dans le README d'Ink upstream : probablement dans le fork `@jrichman/ink` ; non vérifié.
- Pas de source primaire sur la manière exacte dont Claude Code lit l'image du presse-papiers (les commandes `osascript`/`xclip` viennent de billets tiers reproduisant le comportement).
- Comportement d'Ink 7 avec React 18 non testé/documenté (Ink 7 exige React 19.2 ; Ink 6.x exige React 19) — la compatibilité de Fuller (React 18) avec les versions récentes est donc à valider empiriquement.
