# 2.1 à 2.3 — Rendu de la conversation, Markdown, outils

Référence : Claude Code 2.1.281, capturé le 24/09/2026 à 100×40. Requêtes : une réponse Markdown (titre, liste, code, tableau) et une lecture de `README.md` suivie de `ls -la`. Fuller a utilisé Gemini 3.5 Flash : le quota de Gemini 3.6 Flash était épuisé (429). Captures dans `captures/2.1-*.json` et `captures/2.3-*.json`.

## Changement de fond : le plein écran rend les vrais composants

Avant, en plein écran (le mode par défaut depuis l'étape 1.1), Fuller convertissait la conversation en texte brut : pas de Markdown, pas de couleurs, un horodatage devant chaque réponse, des lignes coupées au milieu des mots et un en-tête « Conversation · N rows ». Claude Code affiche la même chose en plein écran et en classique.

Maintenant, chaque élément est rendu avec le composant du mode classique (`TranscriptItemView`, `LiveArea`) via `renderToString`, mis en cache par élément, largeur, mode et thème, puis seules les lignes visibles sont affichées. Le rendu est calculé hors des phases de rendu de React (dans un `setImmediate`) : un rendu Ink imbriqué pendant le rendu de React ne produit rien.

La conversation occupe toute la hauteur disponible (mesurée avec `measureElement`), si bien que la saisie reste en bas de l'écran. Tout ce qui est sous la conversation (animation, dialogues, saisie) est dans un bloc qui ne rétrécit pas ; sinon Yoga écrasait le dialogue de permission.

## Restant

- Mode classique : les outils ne sont pas regroupés (les lignes déjà imprimées dans le terminal ne peuvent plus être modifiées).
- La saisie s'arrête une ligne au-dessus du bas de l'écran : Ink efface et redessine tout l'écran si l'image fait la hauteur exacte du terminal.
- ctrl+o : Claude Code écrit le chemin absolu souligné dans `Read(…)` et une ligne « 03:59 AM claude-opus-5-5 » avant chaque réponse.
- Pendant l'exécution, Claude Code affiche la description de la commande puis `⎿  $ commande` ; à comparer à l'étape suivante.
