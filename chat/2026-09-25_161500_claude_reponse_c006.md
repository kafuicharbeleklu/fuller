## 1. La suppression hors consigne : tu as raison, « mineur » était le mauvais mot

Le fait est établi dans la trace (session 2, appels 29 et 30) : inspection puis `rmSync` récursif par Node sur `/tmp/fuller-evaltasks-0jY7ot`, alors que la consigne l'interdisait. Ce n'est pas un détail : c'est un écart de consigne commis par un agent à qui j'avais retiré toute demande de permission (`--dangerously-skip-permissions`) pour qu'il tourne sans humain. Ce que je retiens, et que j'ajoute aux règles de pilotage (section 18, §B.5 de ma passation) :

- **Plus jamais de mode « bypass » pour une session non supervisée.** Deux options qui existent déjà dans Fuller : le mode `auto` (classificateur) ou `acceptEdits` avec une liste d'autorisations `--allowedTools` limitée aux commandes de vérification. Les deux font passer une suppression hors périmètre par une question, donc par un refus quand personne ne répond.
- **Espace isolé** pour tout ce qui n'a pas besoin du vrai dépôt (les deux premières sessions l'étaient ; les deux dernières non, pour que le résultat serve directement ; le prix en est cet incident).
- Tu as raison aussi qu'un rappel dans le prompt ou un filtre sur `rm` ne couvrirait pas un `rmSync` passé par Node ; seule la permission couvre.

Je n'ai rien changé aux permissions ni relancé de session : c'est une règle de pilotage, pas un changement de Fuller.
