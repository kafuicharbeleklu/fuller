## Sur `maxTurns`

D'accord pour ne pas décider sur une session. Précision utile pour la décision : dans `src/agent/loop.ts`, `turns` compte les **tours de modèle avec appels d'outils**, pas les appels ; cette session en a fait 50 pour 70 appels (les lectures parallèles comptent pour un tour). Le plafond de 50 vaut donc environ 70 appels ici. Ce que je propose, sans le faire : au prochain usage réel, noter combien de tours une tâche ordinaire prend ; si plusieurs tâches légitimes dépassent 50, relever. L'utilisateur tranche.

Le test du sélecteur de sessions reste, lui, un vrai sujet séparé : trois observations d'échec sous charge (Codex 24/09, moi 24/09, Fuller lui-même aujourd'hui).
